# OpenClaw 企业微信虚拟员工 - 故障排查手册

## 📋 快速诊断

**第一时间检查：**
```bash
# 1. 服务状态
docker compose ps

# 2. 最近日志
docker compose logs --tail=50

# 3. 健康检查
curl http://localhost:8080/health

# 4. 系统资源
docker stats --no-stream
```

## 一、服务无法启动

### 问题1.1：Docker 服务未运行

**现象：**
```
Cannot connect to the Docker daemon at unix:///var/run/docker.sock
```

**原因：** Docker 服务未启动

**解决方案：**
```bash
# Ubuntu/Debian
sudo systemctl start docker
sudo systemctl enable docker

# CentOS/RHEL
sudo systemctl start docker
sudo systemctl enable docker

# 验证
docker ps
```

---

### 问题1.2：端口被占用

**现象：**
```
Error starting userland proxy: listen tcp4 0.0.0.0:8080: bind: address already in use
```

**原因：** 8080 端口已被其他进程占用

**解决方案：**

```bash
# 1. 查找占用端口的进程
netstat -tulpn | grep 8080
# 或
lsof -i :8080

# 2. 杀掉进程
sudo kill -9 <PID>

# 3. 或修改配置使用其他端口
vim deployments/docker-compose-minimal.yml
# 修改: ports: "8081:80"

# 4. 重启服务
docker compose up -d
```

---

### 问题1.3：镜像构建失败

**现象：**
```
ERROR [internal] load metadata for docker.io/library/python:3.11-slim
```

**原因：** 网络问题，无法下载镜像

**解决方案：**

```bash
# 1. 配置镜像加速
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json <<-'EOF'
{
  "registry-mirrors": [
    "https://mirror.ccs.tencentyun.com",
    "https://docker.mirrors.ustc.edu.cn",
    "https://hub-mirror.c.163.com"
  ]
}
EOF

# 2. 重启 Docker
sudo systemctl restart docker

# 3. 手动拉取镜像
docker pull python:3.11-slim
docker pull nginx:alpine

# 4. 重新构建
docker compose up -d --build
```

---

### 问题1.4：配置文件错误

**现象：**
```
env file .env not found
```

**原因：** 缺少 .env 配置文件

**解决方案：**

```bash
# 1. 复制模板
cp deployments/.env.example .env

# 2. 填写配置
vim .env

# 3. 重启服务
docker compose restart
```

## 二、企业微信集成问题

### 问题2.1：URL 验证失败

**现象：** 企业微信后台显示"验证失败"

**可能原因：**
1. 服务未启动
2. 外网无法访问
3. Token 或 AES Key 错误
4. 签名验证失败

**排查步骤：**

**步骤1：检查服务是否运行**
```bash
curl http://localhost:8080/health
```

**步骤2：检查外网访问**
```bash
# 在本地电脑测试
curl http://YOUR_SERVER_IP:8080/health
```

如果超时，检查防火墙：
```bash
# Ubuntu
sudo ufw status
sudo ufw allow 8080/tcp

# CentOS
sudo firewall-cmd --list-ports
sudo firewall-cmd --permanent --add-port=8080/tcp
sudo firewall-cmd --reload
```

**步骤3：检查配置参数**
```bash
# 检查 Token 和 AES Key
cat .env | grep WECOM

# Token: 8-32位字母数字
# AES Key: 43位Base64字符

# 确认长度
cat .env | grep WECOM_TOKEN | awk -F= '{print $2}' | wc -c
cat .env | grep ENCODING_AES_KEY | awk -F= '{print $2}' | wc -c
# 应分别输出 8-33 和 44（含换行符）
```

**步骤4：查看日志**
```bash
tail -f logs/wecom/gateway.log

# 查找错误信息
grep -i "error\|fail" logs/wecom/gateway.log | tail -20
```

**步骤5：手动测试验证**
```bash
# 模拟企业微信验证请求（需要替换实际参数）
curl "http://localhost:8080/wecom/callback?msg_signature=xxx&timestamp=xxx&nonce=xxx&echostr=xxx"
```

```bash
# 发送测试消息，观察日志输出
```

**步骤4：检查网络连接**
```bash
# 测试企业微信能否访问你的服务器
# 使用企业微信提供的"测试回调"功能
```

---

### 问题2.3：签名验证失败

**现象：** 日志显示 "Signature verification failed"

**原因：** Token 不匹配或计算错误

**解决方案：**

```bash
# 1. 确认 Token 正确
cat .env | grep WECOM_TOKEN

# 2. 对比企业微信后台的 Token

# 3. 确保没有多余空格
sed -i 's/ //g' .env

# 4. 重启服务
docker compose restart

# 5. 查看日志
tail -f logs/wecom/gateway.log
```

---

### 问题2.4：消息解密失败

**现象：** 日志显示 "Decryption failed"

**原因：** EncodingAESKey 不匹配

**解决方案：**

```bash
# 1. 确认 AES Key 长度（应为43位）
cat .env | grep ENCODING_AES_KEY | awk -F= '{print $2}' | wc -c
# 应输出 44（43位+换行符）

# 2. 重新从企业微信后台复制
# 企业微信管理后台 → 应用详情 → 接收消息 → 查看 EncodingAESKey

# 3. 更新配置
vim .env

# 4. 重启服务
docker compose restart
```

```python
# 路由规则（在 wecom_gateway.py 中）
ROUTE_KEYWORDS = {
```

## 四、数据库问题

### 问题4.1：数据库锁定

**现象：**
```
database is locked
```

**原因：** 多个进程同时访问数据库

**解决方案：**

```bash
# 1. 停止所有服务
docker compose down

# 2. 检查数据库文件
ls -lh data/user_roles.db*

# 3. 删除锁文件（如果存在）
rm -f data/user_roles.db-shm
rm -f data/user_roles.db-wal

# 4. 重启服务
docker compose up -d
```

---

### 问题4.2：数据库损坏

**现象：**
```
database disk image is malformed
```

**原因：** 数据库文件损坏

**解决方案：**

```bash
# 1. 备份损坏的数据库
cp data/user_roles.db data/user_roles.db.corrupted

# 2. 尝试修复
sqlite3 data/user_roles.db "PRAGMA integrity_check;"

# 3. 如果无法修复，从备份恢复
./scripts/restore.sh backups/user_roles_latest.db.gz

# 4. 如果没有备份，重新初始化
rm data/user_roles.db
./scripts/init_database.sh
```

---

### 问题4.3：数据丢失

**现象：** 用户或任务记录丢失

**原因：** 数据库被意外覆盖或清空

**解决方案：**

```bash
# 1. 检查备份
ls -lh backups/

# 2. 恢复最近的备份
./scripts/restore.sh backups/user_roles_20260211.db.gz

# 3. 验证数据
sqlite3 data/user_roles.db "SELECT COUNT(*) FROM user_roles;"
sqlite3 data/user_roles.db "SELECT COUNT(*) FROM task_logs;"
```

## 五、性能问题

### 问题5.1：响应缓慢

**现象：** API 响应时间超过3秒

**排查步骤：**

**步骤1：检查系统资源**
```bash
# CPU 使用率
top -bn1 | grep "Cpu(s)"

# 内存使用率
free -h

# 磁盘 I/O
iostat -x 1 5

# Docker 资源
docker stats --no-stream
```

**步骤2：检查数据库性能**
```bash
# 数据库大小
ls -lh data/user_roles.db

# 任务日志数量
sqlite3 data/user_roles.db "SELECT COUNT(*) FROM task_logs;"

# 优化数据库
sqlite3 data/user_roles.db "VACUUM;"
sqlite3 data/user_roles.db "ANALYZE;"
```

**步骤3：清理旧数据**
```bash
# 删除30天前的任务日志
sqlite3 data/user_roles.db "DELETE FROM task_logs WHERE created_at < datetime('now', '-30 days');"

# 删除90天前的审计日志
sqlite3 data/user_roles.db "DELETE FROM audit_logs WHERE created_at < datetime('now', '-90 days');"
```

---

### 问题5.2：内存溢出

**现象：** 容器频繁重启，日志显示 OOM (Out of Memory)

**解决方案：**

```bash
# 1. 检查内存使用
docker stats

# 2. 增加容器内存限制
vim deployments/docker-compose-minimal.yml

# 添加或修改：
services:
  wecom-gateway:
    deploy:
      resources:
        limits:
          memory: 2G

# 3. 重启服务
docker compose down
docker compose up -d

# 4. 优化代码（如有必要）
# 检查是否有内存泄漏
```

---

### 问题5.3：磁盘空间不足

**现象：**
```
no space left on device
```

**解决方案：**

```bash
# 1. 检查磁盘使用
df -h

# 2. 清理 Docker 镜像和容器
docker system prune -a -f

# 3. 清理日志
./scripts/cleanup_logs.sh --days 7

# 4. 清理旧备份
find backups/ -mtime +90 -delete

# 5. 如果是数据库太大
sqlite3 data/user_roles.db "VACUUM;"
```

## 六、网络问题

### 问题6.1：无法访问外网

**现象：** 无法获取 access_token，日志显示网络超时

**排查步骤：**

```bash
# 1. 测试网络连接
ping -c 3 qyapi.weixin.qq.com

# 2. 测试 DNS
nslookup qyapi.weixin.qq.com

# 3. 测试 HTTPS
curl https://qyapi.weixin.qq.com/cgi-bin/gettoken?corpid=xxx&corpsecret=xxx

# 4. 检查防火墙出站规则
sudo iptables -L OUTPUT -n

# 5. 如果使用代理，检查代理配置
echo $HTTP_PROXY
echo $HTTPS_PROXY
```

---

### 问题6.2：企业微信无法访问服务器

**现象：** URL 验证失败，企业微信提示"请求超时"

**排查步骤：**

```bash
# 1. 检查服务器防火墙
sudo ufw status
sudo ufw allow 8080/tcp

# 2. 检查云服务商安全组
# 登录云服务商控制台
# 安全组 → 入站规则 → 添加 TCP 8080

# 3. 测试公网访问
curl http://YOUR_PUBLIC_IP:8080/health

# 4. 如果使用 Nginx，检查配置
sudo nginx -t
sudo systemctl reload nginx
```

## 七、Docker 问题

### 问题7.1：容器频繁重启

**排查步骤：**

```bash
# 1. 查看容器日志

docker ps -a

docker inspect openclaw-wecom-gateway | grep -A 10 Health

# 4. 手动启动容器（调试模式）
docker compose down
docker compose up  # 不加 -d，查看实时输出
```

### 问题7.2：容器网络问题

**现象：** 容器之间无法通信

## 八、日志分析

### 常见错误日志及解决方案

**错误1：KeyError: 'access_token'**
```
原因：企业微信 API 调用失败，未返回 access_token
解决：检查 CORP_ID 和 SECRET 是否正确
```

**错误2：UnicodeDecodeError**
```
原因：消息解密后编码问题
解决：检查 EncodingAESKey 是否正确
```

**错误3：sqlite3.OperationalError: no such table**
```
原因：数据库未初始化
解决：运行 ./scripts/init_database.sh
```

**错误4：ConnectionRefusedError**
```
原因：无法连接到数据库或其他服务
解决：检查服务是否启动，端口是否正确
```

## 九、紧急故障处理

### 故障分级

| 级别 | 描述 | 响应时间 | 示例 |
|-----|------|---------|------|
| P0 | 严重 | 5分钟 | 服务完全不可用 |
| P1 | 重要 | 30分钟 | 部分功能异常 |
| P2 | 一般 | 2小时 | 性能下降 |
| P3 | 轻微 | 1天 | 日志错误 |

---

### P0 故障处理流程

```bash
# 1. 立即通知相关人员
./scripts/send_alert.sh "P0 故障：服务不可用"

# 2. 快速诊断
docker compose ps
docker compose logs --tail=50
curl http://localhost:8080/health

# 3. 尝试重启
docker compose restart

# 4. 如果重启无效，回滚
docker compose down
git reset --hard HEAD^
docker compose up -d

# 5. 如果回滚无效，恢复备份
./scripts/restore.sh backups/latest.db.gz
docker compose up -d

# 6. 记录故障报告
# - 故障时间
# - 故障现象
# - 排查过程
# - 解决方案
# - 影响范围
# - 改进措施
```
