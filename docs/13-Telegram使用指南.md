## 🚀 快速开始

### 步骤 1: 找到 Bot

在 Telegram 中搜索：
```
@openclaw_assistant_bot
```

或者使用管理员提供的 Bot 链接。

### 步骤 2: 启动对话

点击 "Start" 或发送：
```
/start
```

你会收到欢迎消息，介绍可用的虚拟员工。

### 步骤 3: 选择虚拟员工

发送命令切换到你需要的虚拟员工，例如：
```
/development
```

### 步骤 4: 开始对话

直接发送消息，AI 会根据当前虚拟员工的角色回复你：
```
帮我分析一下这段代码的性能问题
```

## 📝 命令列表

### 基础命令

| 命令 | 说明 | 示例 |
|------|------|------|
| `/start` | 开始使用，显示欢迎信息 | `/start` |
| `/help` | 显示帮助信息 | `/help` |
| `/agents` | 显示所有虚拟员工 | `/agents` |
| `/current` | 显示当前虚拟员工 | `/current` |
| `/reset` | 重置会话 | `/reset` |

### 虚拟员工切换命令

| 命令 | 虚拟员工 | 说明 |
|------|----------|------|
| `/dispatcher` | 调度员 | 智能任务分发和路由 |
| `/operation` | 运营专员 | 数据分析、报表生成 |
| `/product` | 产品经理 | 需求管理、功能设计 |
| `/development` | 开发工程师 | 技术支持、代码审查 |
| `/testing` | 测试工程师 | 质量保障、测试用例 |
| `/service` | 客服专员 | 客户服务、问题解答 |

### 使用技巧

**快速输入命令：**
- 在输入框输入 `/`，会自动显示命令列表
- 点击命令即可快速发送

**查看命令说明：**
- 每个命令都有简短的描述
- 发送 `/help` 查看详细说明

## 🤖 虚拟员工介绍

### 1️⃣ 调度员

**角色：** 智能任务分发和路由

**擅长：**
- 理解用户需求
- 推荐合适的虚拟员工
- 任务优先级排序

**适用场景：**
- 不确定找哪个员工时
- 需要任务规划时
- 多任务协调时

**切换命令：** `/dispatcher`

---

### 2️⃣ 运营专员

**擅长：**
- 数据分析和可视化

**适用场景：**
- 需要数据分析时

**示例对话：**

运营专员: 好的，我来帮您分析...

## ❓ 常见问题

### Q1: 如何切换虚拟员工？

**A:** 发送对应的命令即可，例如 `/development` 切换到开发工程师。

### Q2: 可以同时和多个虚拟员工对话吗？

**A:** 不可以。每次只能与一个虚拟员工对话，但可以随时切换。

### Q3: 如何查看当前是哪个虚拟员工？

**A:** 发送 `/current` 命令。

### Q4: 对话历史会保存吗？

**A:** 会话状态会保存，但建议在一个对话中完成相关问题。

### Q5: 如何重新开始？

**A:** 发送 `/reset` 命令重置会话。

### Q6: Bot 没有回复怎么办？

**A:**
1. 检查网络连接
2. 等待几秒后重试
3. 发送 `/start` 重新开始
4. 联系管理员

### Q7: 可以发送图片或文件吗？

**A:** 目前仅支持文本消息，暂不支持图片和文件。

### Q8: 有消息长度限制吗？

**A:** 建议单条消息不超过 2000 字符，过长的消息可能被截断。

### Q9: 可以在群组中使用吗？

**A:** 目前仅支持私聊，暂不支持群组。

### Q10: 如何提供反馈？

**A:** 联系管理员或访问项目 GitHub 页面提交 Issue。

## 💬 使用技巧

### 1. 明确描述问题

**不好的提问：**
```
代码有问题
```

**好的提问：**
```
这段 JavaScript 代码在处理大数组时性能很慢，
能帮我分析一下原因并给出优化建议吗？
```

### 2. 提供上下文

**不好的提问：**
```
这个功能怎么做？
```

**好的提问：**
```
我们的电商平台需要增加一个购物车功能，
用户可以添加商品、修改数量、删除商品。
请帮我设计一下技术方案。
```

### 3. 分步骤提问

对于复杂问题，建议分步骤提问：
```
1. 先问整体方案
2. 再问具体实现
3. 最后问优化建议
```

### 4. 善用不同虚拟员工

根据问题类型选择合适的虚拟员工：
- 技术问题 → 开发工程师
- 需求问题 → 产品经理
- 测试问题 → 测试工程师
- 数据问题 → 运营专员
